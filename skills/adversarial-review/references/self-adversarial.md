# 自对抗误报模式清单

> 执行流程第五步（自对抗）时加载。对每个 P0/P1 发现逐条过本清单，命中的考虑降级或删除。

## 一、七类常见误报模式

### M1 需求中途变过（误判 F2 需求缩水）
- **症状**：矩阵里某条判「未满足」，但生产 AI 实际是按用户后来的新口径做的
- **检查**：回读对话历史，确认该条需求在交付前没有被用户修改/撤销；找不到修改记录才维持原判
- **风险**：同会话场景下，审查方看的是和生产方同一段历史——变更是可查的，必须查

### M2 约束在别处（误判 F4 过度工程 / 误判 F6 遗忘）
- **症状**：某抽象/配置层看起来多余，实际是为了满足项目 CLAUDE.md、memory 或早前会话里的约定
- **检查**：判"过度"之前，确认项目级约束文件里没有相关要求；同会话任务回读早期约束清单
- **纪律**：查过且确认没有约束依据，才可维持 F4 判断

### M3 证据在视野外（误判 F3 虚假声明）
- **症状**：判"声明无证据"，但证据存在于审查方看不到的工具调用记录里
- **检查**：区分「未验证声明」（我看不到证据）和「虚假声明」（证据与声明矛盾）——看不到 ≠ 没有。除非有直接矛盾证据，最高只能标到「未验证声明」
- **这是本 skill 最重要的一条误报防线**：把未验证说成虚假，审查方自己就在犯 F3

### M4 把"待办"当"虚假完成"（误判 F3）
- **症状**：AI 明确说了"X 部分还没做/下一步做"，审查把它记成"声称完成 X"
- **检查**：核对原声明的措辞——有明确排除/声明的缺口不算 F3，算如实通报；只有"说了做了但没做"才是 F3

### M5 风格偏好混入（D1-D4 越界）
- **症状**：把"我会用另一种写法"包装成正确性问题（命名风格、注释密度、个人偏好的库选择）
- **检查**：删掉这条问题，交付物的行为有任何变化吗？没有 → 是风格意见，不进清单（本 skill 明确不做风格审查）

### M6 低效 ≠ 错误（误判严重度）
- **症状**：实现方式笨但正确，被定成 P1/P2 正确性问题
- **检查**：能否构造出"这个低效在实际负载下导致故障"的攻击路径？不能 → 最多 P3 提示或删除

### M7 审查方自己参与过生产（解释权循环，同会话特有）
- **症状**：审查方对模糊需求的理解 = 生产方的理解（因为是同一个模型、同一段上下文），于是矩阵全绿
- **检查**：对每条"已满足"，问"如果换一个不理解上下文的人来验收，这条还能过吗？"；有歧义的原文标「歧义待裁决」，交给用户，不要自己消歧

## 二、降级/删除规则

1. 命中 M1-M4 之一且检查后无法排除 → **删除**（前提性错误，不是严重性高估）
2. 命中 M5/M6 → **删除或降 P3**（不属于本 skill 审查范围）
3. 严重性高估但不命中任何误报模式 → **降一级**（P1→P2），不直接删除
4. **不可被自对抗冲掉的**：有直接文本证据的矛盾（声明 vs 会话记录、代码 vs 官方文档、需求原文 vs 交付缺失）——这类发现自对抗只能修正表述，不能删除结论

## 三、记录要求

被降级/删除的候选发现写入报告「自对抗记录」段（可选但推荐）：一条一行，写明候选内容 + 处置（删除/降级）+ 理由（命中哪条误报模式）。

价值：让自对抗从不可见的内部推理变成可审计的过程；连续多次审查后，误报模式命中的统计还能反过来校准本清单。
