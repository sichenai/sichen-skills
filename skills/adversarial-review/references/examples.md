# 完整示例（期望的审查效果）

> 首次使用本 skill 或对输出格式不确定时加载。三个示例覆盖主要场景：同会话验收代码、审查方案、跨工具贴入。
> **注意输出中的中文化纪律**：所有代号中文名在前、代号退括号——「严重（P1）」「需求缩水（F2）」——报告是给用户看的，不是内部工作底稿。

## 示例 1：验收 agent 交付的代码（同会话，三方输入齐全）

**输入语境**：agent 完成任务后声明「已实现 RSS 监控脚本，已测试去重逻辑正常」。

```markdown
### 需求符合性矩阵
| # | 原始需求条目（逐字引用） | 状态 | 差异说明 |

## 问题清单（正确性/安全性/健壮性/现实性四维发现）

### 问题1【严重 P1】：声明"已测试"但测试实际未发生
- **位置**：完成声明 + 会话记录
- **攻击路径**：用户采信"已测试"声明 → 部署到 cron → 问题2 在 cron 环境必现 → 但用户因信任声明优先怀疑别处 → 排查时间翻倍
- **失效模式**：虚假完成声明（F3）
- **风险等级**：严重（P1）· 概率高（已声明且无证据） × 损害中（误导排查方向）
- **置信度**：高（会话记录可复核）
- **修复方向**：要求 agent 实际运行去重测试并贴出命令与输出

### 问题2【严重 P1】：seen.json 相对路径导致换目录运行时去重静默失效
- **位置**：monitor.py:34
- **攻击路径**：cron 以其他工作目录启动脚本 → 相对路径在新目录解析 → seen.json 重新创建 → 历史记录丢失 → 同一批条目全部重复推送 → 用户以为是新内容
- **失效模式**：——（正确性·边界条件）
- **风险等级**：严重（P1）· 概率高（非项目目录运行必现） × 损害中（重复推送+历史丢失，但故障显性可修）
- **置信度**：高（代码可直接确认）
- **修复方向**：路径改为基于 __file__ 或绝对路径

## 自对抗记录
- 候选发现「feedparser 版本兼容性风险」：删除——当前用法为稳定 API，多版本兼容，属凑数性质（无具体攻击路径）
- 候选发现「requests 无超时设置」初判严重：降级删除——自对抗确认代码设置了 timeout=10（误读）

## 未覆盖的盲区

## 验收建议
```

## 示例 2：审查 agent 写的技术方案（谄媚识别）

**输入语境**：agent 给出「选题系统重构方案」，推荐引入消息队列 + 微服务拆分。

**期望输出节选**：

```markdown
### 问题1【严重 P1】：方案未呈现替代路线，存在谄媚倾向
- **位置**：方案第 2 节「架构选型」
- **攻击路径**：方案只给了 MQ + 微服务一条路线 → 用户无从对比 → 实施后发现单机定时任务 + SQLite 即可满足当前规模（日均 < 1000 条）→ 为不存在的需求背上长期运维成本
- **失效模式**：谄媚隐藏 trade-off（F5）+ 过度工程（F4）
- **风险等级**：严重（P1）· 概率中（取决于真实规模） × 损害高（架构一旦落地回退成本极大）
- **置信度**：中（依赖假设：当前处理规模确实很小——方案中未给出容量估算，这本身也是问题）
- **修复方向**：要求方案补齐「单机方案」作为对照路线，并给出规模阈值（什么量级才需要 MQ）

### 问题2【一般 P2】：方案风险评估为套话
- **位置**：方案第 5 节「风险与对策」
- **攻击路径**：只写"注意性能和安全"无具体风险 → 用户误以为风险已评估 → 实际最大的风险（MQ 消息堆积时选题推送延迟）从未被讨论
- **失效模式**：谄媚隐藏 trade-off（F5）
- **风险等级**：一般（P2）· 概率高 × 损害低
- **置信度**：高
- **修复方向**：重写为具体风险清单，每条带触发条件

## 未覆盖的盲区
- 方案声称"调研了 3 个同类系统"，未给出可访问的调研材料链接，声明核验只能标未验证，无法确认真伪
```

```markdown
- **攻击路径**：代码直接运行 → AttributeError → 用户误以为是版本问题 → 升级 pandas 后仍报错 → 排查时间浪费在错误方向
```
